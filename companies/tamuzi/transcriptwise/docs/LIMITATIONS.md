# Known limitations and deliberate non-features

- **No live AI or authorized-caption credentials were available for verification.** Adapter HTTP contracts and failures are deterministically tested; that does not prove a particular model/account/quota works live. Public metadata is attempted honestly, not guaranteed.
- **Local mode is not an LLM.** It is an explicit extractive development alternative. It cannot reliably infer foundations, explain unfamiliar technical concepts, translate, check facts, or follow free-form teaching instructions. Configured AI provides that generation path but still needs human review.
- **No arbitrary-public-video caption scraper.** Official API access, actual account permissions, and a deliberate server video-sharing allowlist are required. No per-user Google OAuth UI or third-party transcript marketplace adapter is implemented.
- **No independent fact-checking/browsing.** Further-research sections are suggested questions, not fetched external citations. Source claims and model teaching can be wrong.
- **Single process/instance only.** In-process limits, queue recovery and worker ownership are not multi-replica safe. No Redis/vector store/queue infrastructure is silently required.
- **Auth is basic first-party accounts, not a complete identity suite.** No verified email ownership, recovery/password-change flow, MFA, SSO, or device-session dashboard. Choose an appropriate identity strategy before broad public deployment.
- **Not deployed or certified.** Container/ingress/CI recipes are supplied; Docker execution, public TLS deployment, independent penetration testing, accessibility certification, backups in a real hosting environment and load testing remain operator work.
- **Browser verification is Chromium desktop plus mobile emulation.** It is not a real-device, Safari/Firefox, full screen-reader, every-state, 200%-zoom or touch-hardware certification. Automated axe scans are useful but incomplete. Very large guide sections may need future virtualization.
- **Bounded input/output.** Default source limit is 300,000 characters/2 MB uploads. Rejected input is not clipped. All accepted source segments are chunked. Combined output beyond 300 items/section or 150 questions/cards is evenly sampled with a visible disclosure, not hidden tail truncation. Initial unabridged chunk results are in JSON export; later edits/regenerations are not a full version-history archive.
- **Character-based context planning.** Operators must tune chunk/output budgets for their actual model tokenizer/window. Compatible providers must accept the implemented chat-completions parameters; other protocols need an adapter. Section regeneration reprocesses the source and can cost more; it is not initial-chunk checkpoint reuse.
- **No native server PDF generator.** Markdown, DOCX, JSON and standalone print HTML work. PDF is your browser's Print/Save-as-PDF operation. DOCX preserves readable text/source URLs/code, but is not a pixel-identical rendering of every Markdown construct or an editable slide deck.
- **No exam security or mastery claims.** Quiz answers exist in the guide API and are hidden by the study UI until submission. Only objective answers are automatically graded. Flashcard scheduling is a simple practice heuristic, not a validated scientific prediction of mastery. Old attempts/reviews remain historical after regeneration.
- **Basic relational search and folders.** Folders are guide labels, not a nested filesystem; tags are simple labels. No semantic search, shared workspaces, collaborative edits, public share links, browser extension, transcription from audio/video, OCR or native mobile app is provided.
- **No instant cancel of an already-sent external request.** Navigating away stops watching a retrieval in that composer; it is not billed-request cancellation. Deletion prevents late data resurrection, but a provider call can still finish/incur cost. Interrupted tasks are recoverable after restart.
- **No encryption/backup magic.** Database text, exports, operator logs, external provider retention and backups require an appropriate operational policy. Deletion cannot erase someone else's downloaded copy or a provider's retained request.

Priorities: test chosen live integrations; complete identity recovery/verification; container/TLS smoke tests and restore drills; independent security/accessibility review; then workload-driven search/virtualization/worker improvements. Do not introduce distributed infrastructure merely to make a diagram look sophisticated.
