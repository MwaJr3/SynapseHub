# Case Study: Stock Price Analysis — Comparative Time-Series Analytics

## 1. Project overview

This project turns a beginner stock-chart exercise into a reproducible analytical workflow. A polished Jupyter Notebook explains the analysis while a tested Python package handles retrieval, validation, transformations, statistics, visualization, and reporting. The work is historical and educational; it neither predicts prices nor recommends trades.

## 2. Problem statement

Financial data looks tabular but depends on chronology, market calendars, provider conventions, adjustment choices, and window definitions. A chart can be visually convincing even when tickers are mis-mapped, dates are unsorted, comparisons start on different days, volumes are aggregated incorrectly, or rolling metrics use incomplete windows. The project therefore treats data quality and methodology as first-class engineering requirements.

## 3. Analytical objectives

- Retrieve any configured ticker list and date range through `yfinance`.
- Preserve a valid, sorted, unique `DatetimeIndex` without inventing missing sessions.
- Compare nominal and common-date normalized closing prices.
- Build correct Friday-ending weekly and month-end OHLCV bars.
- Calculate trailing 20- and 200-session simple moving averages without look-ahead.
- Compare raw, normalized, and weekly share volume.
- Calculate returns, CAGR, historical volatility, drawdown, turnover approximation, and return correlation.
- Generate evidence-based findings and reusable outputs.

## 4. Data source and collection

Live mode calls Yahoo Finance through `yfinance` with explicit dates, daily interval, adjustment choice, disabled actions, deterministic per-ticker requests, timeout, and optional cache controls. Each ticker is requested separately so partial failures are identifiable. Source, requested and observed dates, retrieval time, row count, interval, adjustment, and library versions are recorded.

Yahoo Finance was inaccessible in the restricted build environment. The committed notebook therefore explicitly loads documented AAPL/MSFT archived observations from an MIT-licensed source. It does not report those files as a live download, and live mode never falls back silently. Provider behavior is covered with injected mock responses; fresh live-data verification remains outstanding.

## 5. Data-cleaning approach

The normalization layer handles explicit `Date` columns, provider date indexes, and common yfinance MultiIndex orientations. Validation rejects empty data, missing required fields, non-datetime indexes, unsorted or duplicate timestamps, nonnumeric/infinite values, missing OHLCV values, non-positive prices, negative volume, illogical high/low relationships, and insufficient observations. Unusual long calendar gaps are warnings for investigation.

No forward fill, interpolation, or synthetic price creation occurs. Weekends and exchange holidays remain absent because they are legitimate non-trading periods. Duplicate handling requires an explicit policy.

## 6. Time-series transformations

Daily frames are indexed chronologically. Weekly `W-FRI` and monthly `ME` resampling use open=first, high=max, low=min, close=last, and volume=sum. Partial boundary periods are retained by documented default. Common-date price and return comparisons use inner alignment, preventing cumulative series from starting on different dates.

## 7. Moving-average calculations

`SMA_20` and `SMA_200` use Pandas trailing windows with `min_periods` equal to the full window. The first 19 and 199 observations respectively remain missing. A test changes future prices and confirms earlier moving averages do not change, providing a direct no-look-ahead check. The notebook labels moving averages as lagging descriptions rather than trading signals.

## 8. Visualization examples

The generated chart set includes individual daily closes, nominal price comparison, common-date normalized performance, daily/weekly/monthly frequency panels, per-ticker moving averages, daily and weekly volume, own-mean normalized volume, rolling annualized volatility, running-peak drawdowns, and a daily-return correlation matrix.

The portfolio thumbnail is the actual normalized-performance PNG generated by the notebook. Every figure includes labeled axes, methodology notes, consistent ticker colors, date formatting, and a non-misleading scale.

## 9. Additional statistical analysis

The summary includes first/last/min/max close, absolute and percentage price changes, CAGR, mean/median daily return, daily return standard deviation, annualized volatility using √252, maximum drawdown, mean/median/total share volume, and approximate mean daily turnover (`Close × Volume`). A correlation matrix is calculated from inner-aligned daily returns.

## 10. Important engineering decisions

1. **Notebook as orchestrator:** logic lives in importable modules, avoiding hidden notebook state and duplicated implementations.
2. **Per-ticker requests:** failures and mappings are explicit rather than buried in one provider-wide response.
3. **No silent fallback:** archived sample mode is selected intentionally; a failed live request remains a failure.
4. **Raw/derived separation:** caches, normalized data, tables, figures, and reports have distinct locations.
5. **Bounded central configuration:** tickers, dates, price basis, intervals, windows, caching, paths, and chart DPI are validated once.
6. **Computed interpretation:** the report builds claims from calculated values and labels limitations; no news narrative is invented.

## 11. Testing strategy

Thirty-nine pytest tests use controlled OHLCV frames and mocked provider calls. Coverage includes schema and index validation, duplicate/missing policies, common-date alignment, exact weekly/monthly aggregation, moving-average warm-up and no-look-ahead, known returns and drawdowns, summary metrics, rolling volatility, correlation, successful/empty/network/MultiIndex/partial downloads, cache reuse/refresh, exports, and report disclaimers. No test requires Yahoo Finance.

Ruff formatting and lint checks provide additional static quality control. The notebook is executed from top to bottom in a clean kernel and validated with `nbformat`.

## 12. Findings from the archived sample

For the common 2024-01-02 to 2026-08-28 sample:

- AAPL's price-only change was 72.2%, compared with MSFT's 38.5%.
- AAPL had slightly greater annualized daily-return variability: 27.7% versus 26.9%.
- AAPL averaged 54.3 million shares/day; MSFT averaged 25.2 million. This does not establish investor intent, company size, or liquidity quality.
- Both final closes were above their respective 200-session moving averages. This is a historical relationship, not a signal.
- Daily returns had a 0.34 Pearson correlation on common dates. This is historical association, not causation.

Weekly and monthly outputs reduced point density while retaining period-last closes. Historical prices alone cannot establish why any observed movement occurred.

## 13. Limitations

The executed run is archived rather than freshly downloaded. Provider data can be delayed, corrected, unavailable, or adjusted differently elsewhere. Unadjusted close is price-only and can omit distributions. The sample has selection and survivorship limitations. Approximate turnover is not a complete liquidity model. Historical volatility, drawdown, and correlation are period-dependent and not forecasts.

## 14. Lessons learned

Correct financial analysis depends as much on index semantics, alignment, data provenance, explicit failure states, and careful language as on formulas. Resampling each OHLCV field according to its meaning prevents subtle errors. Full-window rolling calculations and mock-driven tests make the analytical assumptions inspectable. Separating facts from explanations prevents charts from becoming unsupported stories.
