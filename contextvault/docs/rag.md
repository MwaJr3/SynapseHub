# Retrieval, generation and citations

Text extraction normalizes Unicode and whitespace, preserves PDF page numbers and Markdown headings where available, and produces paragraphs. The chunker respects page/section changes, packs paragraphs up to the configured character size, splits long paragraphs on sentence/word boundaries, and applies overlap where it fits. Token counts are approximate (`characters / 4`), not provider tokenizer counts. DOCX extraction is plain text and does not currently preserve heading or page structure.

Every embedding stores its model identifier. `text-embedding-3-small` uses 1536 dimensions; the mock hash has the same *shape* only, not the same vector space. Local embedding endpoints must output 1536 values and use a stable, versioned model identifier. Reprocess documents after any model change; merely matching dimensions does not make two models compatible.

Retrieval first authorizes the owner and collection. Vector and hybrid search embed the normalized question and rank vector candidates by cosine distance (`<=>`); lexical candidates use English `websearch_to_tsquery` and a generated `tsvector`. Keyword-only search does not call an embedding provider and can search ready text indexed by an older embedding model. Hybrid combines candidates using reciprocal-rank fusion `1/(60 + rank)`: the cosine threshold filters the **vector list**, but an independent keyword match can still appear below that threshold. Optional lexical reranking adds a small normalized query-term overlap boost. In hybrid results, older-model lexical hits have no cosine score; vectors from different model identifiers are never compared. Document, type, creation-date and tag filters apply inside the scoped SQL. Search is capped at eight final chunks. ANN indexes can return approximate candidates and metadata filters can reduce recall.

The developer playground's **Compare retrieval** runs keyword, vector and hybrid on the same query and filters. It sends the question to the configured embedding provider once and shares that vector between vector and hybrid; it does not call a generation model. If embedding fails, keyword results can still be shown alongside errors for the other strategies. Displayed per-strategy search times exclude the shared embedding, may include contention, and are not benchmarks. Full-text, cosine and fused rank scores have different meanings and are not comparable probabilities.

A short follow-up containing pronouns or few meaningful tokens is augmented with the last user question. Only prior user questions from the latest four prior messages are provided to the model, each truncated, and fresh evidence is retrieved on every turn. Earlier assistant text is not forwarded: it may contain excerpts from sources that were later moved or deleted. User-authored questions remain in history and may themselves contain sensitive text. This simple heuristic is not a conversational-query rewriting model and may fail on ambiguous follow-ups.

The system prompt explicitly treats source text as untrusted data. The mock produces extractive sentences; OpenAI/self-hosted adapters receive the system instruction and a JSON representation of evidence. The output validator refuses an answer containing an out-of-range numeric citation or no valid citation. Citation labels map to actual saved chunk IDs; the source drawer shows the real passage and metadata. Before a chat answer is saved, or playground/comparison evidence is returned, source documents and chunks are checked and locked in the selected collection; changed, moved, archived, deleted or reprocessed evidence causes a retryable conflict. Historical source previews are unavailable while their document is outside the conversation's collection, archived, deleted or being reprocessed. Previously generated message text can still contain excerpts. This **does not** prove that a cited passage entails the claim, that every claim is supported, or that the model cannot be manipulated. Similarity is not an answer-correctness probability. Human verification remains necessary.

Responses are buffered so citation labels can be checked before display; token streaming is not implemented. Stop aborts the browser request. If the hosting runtime propagates that disconnect to the server's `Request.signal`, ContextVault forwards it to embedding/generation fetches and checks it before saving an answer. Some proxies or runtimes may not propagate disconnects, a provider may already have received the data or finished work, and in-progress database operations are not interrupted. Cancellation is therefore best effort, not a guarantee of stopping server work or billing. An interrupted question may remain in history and can be retried.
